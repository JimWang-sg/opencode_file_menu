技术架构

┌─ renderer（filetree-menu.js 注入 + bundle 补丁）────────┐ │ 右键菜单: 编辑 / 预览（按扩展名显示） │ │ 就地编辑器: 行号列 + textarea + 状态栏 + 滚动恢复 │ │ MD 预览: __ocParseMarkdown（bundle 现成管线） │ │ Web 预览: <iframe src="oc-file://…"> sandbox 隔离 │ │ 文件树: tree.dir 暴露 + 5s 轮询兜底 │ └───────────────┬────────────────────────────────────────┘ │ fs IPC │ 资源加载 ▼ ▼ ┌─ main（index.js + node chunk 打补丁）────────────────────┐ │ ipcMain.handle("fs-*") read/write/mkdir/rm/… │ │ protocol.handle("oc-file") serve 任意绝对路径 │ │ 文件监听: watcher 移除 VCS 要求（任意目录） │ │ OPENCODE_DEBUG_PORT=9222 调试后门（仅显式启用） │ └───────────────────────────────────────────────────────┘
oc-file:// 协议：oc-file://local/<绝对路径按段 encodeURIComponent>，win32 校验盘符绝对路径，目录自动找 index.html，响应带 CORS 头，MIME 覆盖 html/css/js/图片/字体/音视频。
安全：iframe sandbox="allow-scripts allow-same-origin allow-forms allow-popups allow-pointer-lock"，跨源隔离——页面脚本无法触碰主界面 DOM。
文件树实时刷新修复：opencode 原版文件监听器只在 location2.vcs && Flag.OPENCODE_EXPERIMENTAL_FILEWATCHER 时订阅——非 git 目录下文件树不实时更新。补丁将条件改为只判 Flag.OPENCODE_EXPERIMENTAL_FILEWATCHER，任意目录都订阅 watcher；renderer 侧暴露 tree.dir 供轮询兜底枚举已加载目录、对缺失 dir store 加防御、兜底间隔 20s → 5s。
原版终端修复（app.asar.unpacked 加载 conpty）：打包后主进程 JS 位于 asar 虚拟文件系统内，内嵌服务端运行时（原生 Node/Bun）的 require 不具 asar 重定向能力，dlopen asar 内部路径的 .node 报 error 126 → 原版终端 PTY 全 500。补丁在 @lydell/node-pty-win32-x64/lib/utils.js 的 loadNativeModule 中把 __dirname.replace(/app\.asar/, "app.asar.unpacked") 作为首选基路径——.node 由 electron-builder 解包到 app.asar.unpacked，据此直接 dlopen。打包须 --unpack="**/*.node" --unpack="**/prebuilds/**"：asar 内有记录（Electron 主进程 require('@parcel/watcher-win32-x64') 等懒加载才不会静默失败）而实体在 unpacked。修复后原版 #terminal-panel（ghostty-web WASM 渲染 + POST http://127.0.0.1:50757/pty 流式 PTY）即恢复，"新建终端"多开标签页。

│  ├─ apply_livefix.py     # 文件树实时刷新修复（watcher 去 VCS 要求 + 轮询兜底）
│  ├─ install_patch.ps1    # 部署辅助
│  └─ cdp_*.mjs            # CDP 端到端验证（preview / gutter / verify …）
└─ tools/                  # @electron/asar 打包工具

部署到安装版

  1. 解压当前 app.asar（asar extract）
  2. python patch/scripts/apply_patch.py（全新目录）或 apply_patch2.py（已带旧补丁）
  3. python patch/scripts/apply_livefix.py 应用文件树实时刷新修复
  4. npx asar pack app.asar.extracted app.asar.new 重新打包
  5. 替换安装目录 resources/app.asar，备份原文件

OOPIF 陷阱：custom scheme 的 iframe 是独立渲染进程，主 target 的 CDP 看不到它，必须 Target.attachToTarget 进 iframe 内部验证——cdp_preview_verify.mjs 即此做法。
